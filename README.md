# AskLocal

A local workplace knowledge app: ask a question, retrieve company information, get an answer with sources, and turn confirmed discussion answers into reusable knowledge.

## Getting started

Follow the setup instructions below for your operating system. A fresh download starts with an account-creation wizard and asks you to choose your own admin password. You can start with an empty workspace or fictional demo data.

After setup, open **http://127.0.0.1:8000** in your browser. On macOS, **Start AskLocal.command** can start the app again. If the app is already running, open the address instead of starting a second copy.

## Quick setup for recording the video

A ready-made fictional database and accounts are included in `demo/`. Use **`sh setup.sh --demo`** on macOS/Linux, or **`py -3 scripts/manage.py setup --demo`** on Windows. Then download the models and start the app using the commands below.

Sign in as **admin@demo.test**, **amy@demo.test** or **jordan@demo.test**, all with password **demo-only-123**. This skips account creation on a fresh installation. Existing workspaces are preserved. See [the recording walkthrough](demo/README.md).

## What works

- React interface matching the reference layout: sidebar, prominent question box, question cards and staff discussion cards.
- Local SQLite persistence for users, documents, questions, replies, approved answers and feedback.
- Real local RAG with keyword search and optional semantic embeddings through Ollama.
- Company answers generated by the selected local model, with accessible source links.
- Questions without supporting evidence are routed to discussions, general answers or clarification.
- Replies are saved immediately. Only the admin-confirmed answer is indexed as official knowledge.
- Employee/department access enforced by the backend, including direct source URLs.
- Text PDF, Markdown and plain-text uploads.
- Incorrect/outdated answer reports for admin review.
- Optional OpenAI answers and public web search, disabled by default.

## Run it on another computer

### Prerequisites

1. **Python 3.12 or newer**, with pip and venv.
2. **Node.js 22.12 or newer**. Node 24 is used on the development machine.
3. **pnpm 11.19.0**: after installing Node, run `npm install -g pnpm@11.19.0`.
4. **Ollama**, installed natively from [ollama.com](https://ollama.com). Start the Ollama application/service.

Ollama is used for local generation and embeddings. A 4B model is the starting configuration; actual speed and memory depend on the computer and context size. Allow approximately 4 GB of disk space for these two model downloads, plus dependencies and runtime memory. CPU-only machines may be slower.

### macOS / Linux

Open a terminal in the downloaded project folder:

```sh
./setup.sh
python3 scripts/manage.py models
./start.sh
```

If downloaded file permissions prevent execution, use `sh setup.sh` and `sh start.sh`.

### Windows

Open PowerShell in the project folder:

```powershell
py -3 scripts/manage.py setup
py -3 scripts/manage.py models
py -3 scripts/manage.py start
```

The same commands are provided in `setup.ps1` and `start.ps1`. Direct Python commands work without changing your PowerShell execution policy.

### First launch

1. Create your admin account and decide whether to include fictional demo data.
2. Open **Settings** and confirm Ollama is connected and the chosen models are downloaded.
3. Click **Build semantic index**. Keyword retrieval works before this finishes.
4. Ask a question, open its source, and try a discussion.

Setup does not overwrite existing configuration or workspace data. Model files are downloaded by Ollama and are not included in the repository.

## Demo walkthrough

1. Ask **Where is Amy?** → the answer should cite **Your first week**.
2. Ask **How do I claim an expense?** → the answer should cite **Expense claims**.
3. Ask **Can we work remotely during an office closure?** → the archive initially has no approved answer. Join the existing question or start a discussion.
4. Add a reply. As the admin, enter a reviewed, confirmed answer in the approval form.
5. Ask again → the answer can now cite the approved discussion. Build the semantic index to embed the new passage too.
6. Sign in as Amy → the fictional leadership planning document is absent, and a direct source URL is denied.

Staff discussions such as Friday lunch remain conversations. They are not automatically company policy evidence.

## Optional OpenAI mode and public web search

Copy `.env.example` to `.env`, then add your own key:

```dotenv
OPENAI_API_KEY=your-own-key-here
```

Restart the app. In **Settings**, choose OpenAI or separately enable public web search. The default model is `gpt-6-luna`; it is configurable. You pay your own API/tool usage costs. Keys are read only by the backend and are never returned to the browser. Do not commit `.env`.

Cloud answer mode sends the question and selected retrieved passages to OpenAI. Web search sends only the separate public question, without company passages or private chat history. The user explicitly chooses the general-answer action. Keep private information out of that question. `store: false` is set, but this does not eliminate every form of provider retention. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data).

Local mode calls only the loopback Ollama endpoint for generation/embeddings and never silently falls back to OpenAI. Keep the configured Ollama models local, not cloud tags. Public web search is an independent online option and must be off for fully offline operation.

## Development in VS Code

Open this folder in VS Code. Backend source is in `backend/`; interface source is in `frontend/src/`.

Tasks: **AskLocal: Setup**, **AskLocal: Start**, **AskLocal: Test**. The backend debug configuration uses the Python extension if installed.

For interface live reload, run the backend and `pnpm dev` in separate terminals, then use `http://127.0.0.1:5173`. The development server proxies `/api` to the local backend.

```sh
pnpm build
python3 scripts/manage.py test
python3 scripts/manage.py doctor
```

React renders text safely; document text and model instructions never execute as code. Provider outputs are validated before their route or citations are used. The backend owns permissions and approvals.

## Data and backups

Workspace data stays outside the checkout:

- macOS: `~/Library/Application Support/AskLocal/asklocal.sqlite3`
- Windows: `%LOCALAPPDATA%\AskLocal\asklocal.sqlite3`
- Linux: `~/.local/share/asklocal/asklocal.sqlite3` (or `$XDG_DATA_HOME/asklocal`)
- Override for testing: `ASKLOCAL_DATA_DIR`.

Documents are stored as extracted text in SQLite; uploaded originals are not kept. Sessions are stored as hashed tokens. User passwords use salted scrypt hashes. Questions/history are private to their author. Reporting an answer shares its question with the admin for review. Withdrawing a source removes it from retrieval and redacts dependent saved answers when reopened.

Back up the database, including active-write-safe SQLite copying:

```sh
python3 scripts/manage.py backup --destination /path/to/new-backup.sqlite3
```

To restore, stop AskLocal, preserve the existing data directory, then place the backup database in a separate data directory and launch with `ASKLOCAL_DATA_DIR` pointing there. This avoids mixing a restored file with existing SQLite journal files. The backup contains private workspace data; keep it out of GitHub. Rebuild the semantic index after changing embedding models.

## GitHub sharing

The `.gitignore` excludes configuration secrets, runtime databases, dependency folders and generated output. The only database included is `demo/asklocal.sqlite3`, generated from fictional data with ready-made demo accounts. It contains no API keys, sessions or saved chats. The fictional company seed is in `backend/store.py`.

Each download creates an independent local workspace. GitHub does not host its Python server or local model. This version binds to your computer's loopback interface. A shared organisation server is a separate deployment with additional authentication, HTTPS and operational work.

## Verification and limits

Tested on an Apple M1 Pro MacBook Pro with 16 GB RAM, Python 3.14 and Node 24. The automated suite covers access/CSRF enforcement, discussion approval, withdrawn sources, private history, uploads, persistence and absence of automatic cloud fallback. Windows/Linux scripts are provided, but those platforms have not been independently verified yet.

This is a functioning local prototype, not a production enterprise system. Local models can still make mistakes. Source identifiers are validated, but semantic truth is not guaranteed. Scanned PDF OCR, SSO, password recovery, streaming responses, department changes, distributed indexing and shared-company deployment are not implemented. Optional cloud calls require your own API key; a basic OpenAI answer has been tested on the development machine. There is no app-enforced API spending cap yet.

If a model disconnects, the app shows an error. If semantic embeddings are unavailable, retrieval uses keyword search and does not send data elsewhere. After uploading or approving new information, it is immediately in keyword retrieval; click **Build semantic index** to add its semantic vectors.

## Troubleshooting

- **Address already in use:** open the running app; do not start a second backend on port 8000.
- **AI unavailable:** run `doctor`, start Ollama and verify the configured answer model.
- **Index failed:** download `qwen3-embedding:0.6b`, then rebuild in Settings.
- **PDF has no readable text:** run text recognition separately or upload Markdown/plain text.
- **Missing dependencies or frontend:** rerun setup; existing data is preserved.
- **Changes not visible:** rebuild the frontend and restart the backend, then reload the browser.
